# 文档编写指南

本仓库用于存放项目总体设计与需求文档与各模块的设计说明文档，供开发者和 AI 协作使用。

---

## 一、核心原则

1. **格式精简**，用表格优先，避免长段落。
2. **禁止变更类表述**，禁止在任何文档中写任何“变更叙事”式表述。文档只描述当前事实与规范，不描述自身的历史演变。禁止的句式包括但不限于：
    - “之前……，我们修改了……”
    - “原先的做法是……，现在改为……”
    - “旧版本中……，现已……”
    - “此前存在……问题，因此……”
    - “经过讨论/评审，决定……”
    - “本次调整了……”
    - 任何以时间、阶段、迭代为线索组织文档内容的写法。
3. **内容精简**，在描述清晰的情况下，字越少越好，避免重复描述与没必要的描述。
4. **设计文档及子文档只定义上层契约**，如接口、配置、部署等，不描述内部实现细节，仅包含模块调用者所需要了解的内容。
5. **谨慎添加**，增加内容时，只添加真正必要的内容。

---

## 二、文档类型与目录结构

### 2.1 文档类型

| 类型 | 说明 |
|------|------|
| 总体设计与需求文档 | 项目全局设计，从顶层全局性地描述各个模块之间的关系 |
| 模块设计文档 | 各模块的上层契约（接口、配置、部署） |

### 2.2 目录结构

    设计文档仓库/
    ├── README.md                     # 本文件
    ├── 总体设计与需求文档.md          # 项目的全局设计文档
    ├── externals/          # 外部依赖说明，仅读取，勿动
    └── modules/                      # 子模块设计文档
        ├── A模块-设计.md              # 当前版本（主文件）
        ├── A模块/                    # A模块详细内容
        │   ├── shared/               # 模块内共享内容
        │   │   ├── error-codes.md
        │   │   └── ...
        │   ├── auth.md               # 功能域文件
        │   └── ...
        ├── B模块-设计.md              # 当前版本（主文件）
        ├── B模块/                    # B模块详细内容
        └── archive/                  # 历史版本归档
            ├── A模块-v1.0.0-20260101.md
            └── ...

### 2.3 命名规则

| 类型 | 命名格式 | 示例 |
| --- | --- | --- |
| 总体设计文档 | `总体设计与需求文档.md` | 固定名称 |
| 模块当前版本 | `{模块名}-设计.md` | `用户服务-设计.md` |
| 模块归档版本 | `{模块名}-v{版本号}-{YYYYMMDD}.md` | `用户服务-v1.1.0-20260215.md` |

**说明**：
- 模块名：中文或英文均可，保持稳定
- 版本号：语义化版本 `v主版本.次版本.修订号`
- 日期：归档当天的日期 `YYYYMMDD`

## 三、总体设计与需求文档编写指南

### 3.1 编写原则

1. 从框架出发，不要描述底层细节
2. 确保文档的稳定性，避免描述容易频繁修改的细节

### 3.2 文档结构

总体设计文档应包含以下核心章节：

| 章节 | 内容要点 |
|------|----------|
| 1. 项目概览与核心功能 | 项目定位、核心功能列表、仓库结构 |
| 2. 技术选型与架构流程 | 技术栈表格、顶层架构流程 |
| 3. 开发规范集合 | 命名规范、环境变量规范、模块规范 |
| 4. 部署方式 | 部署触发方式、目标环境、流程 |

## 四、模块设计文档结构

每个 `{模块名}-设计.md` 为主文件，采用渐进式披露设计：主文件只保留梗概，详细内容拆分到子目录的子文件中。子文件只对契约（接口、配置、部署）细节进行补充描述，不描述内部实现细节。

### 4.1 主文件结构

主文件必须包含以下章节，保持精简（建议不超过 150 行）：

| 章节 | 必须 | 说明 |
| --- | --- | --- |
| 版本与日期 | 是 | 当前版本号和日期，放在文档顶部 |
| 1. 功能 | 是 | 一句话核心能力 |
| 2. 架构概览 | 是 | 数据流/组件关系图，简要 |
| 3. 端点/组件/功能/页面概览 | 是 | 表格：方法、路径、功能、详情文件（根据模块情况，编写不同类型的概览内容） |
| 4. 配置概览 | 否 | 表格：变量名、敏感、说明，简要仅列名称（如模块需单独配置时填写） |
| 5. 部署概览 | 否 | 前提 + 流程要点，简要（如模块需单独部署时填写） |
| 6. 子文件索引 | 是 | 子目录文件清单及用途 |

**端点概览表格格式：**

| 端点 | 方法 | 说明 | 详情 |
| --- | --- | --- | --- |
| `/api/v1/auth/register` | POST | 用户注册 | auth.md |
| `/api/v1/tasks` | POST | 创建任务 | tasks.md |

> 最后一列"详情"标注对应子文件名，AI 可直接按 `{模块名}/{功能域}.md` 路径读取。
> 如需共享内容，按 `{模块名}/shared/{文件名}` 路径读取。

## 五、模块设计文档版本迭代操作流程

### 小版本
仅更新版本号，内容直接修改，不归档历史版本。默认采用该方式更新文档。

### 大版本
执行以下步骤：
1. 复制 当前文档 → 复制到 archive/
2. 重命名副本为：`{模块名}-v{旧版本号}-{当前日期}.md`
3. 修改模块设计文档：
    - 更新顶部版本号（如 v1.1.0 → v2.0.0）
    - 更新顶部日期为当天
    - 修改正文及子文件内容（接口、配置等）
4. 检查模块设计文档及其子文档是否只保留其他模块或用户使用该模块时所必须了解的内容，删除的内部实现细节及不必要的子文件。
